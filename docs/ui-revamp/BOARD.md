## Gaps and blockers
- Backend contract in BRIEF §7 is being built on `feat/platform-hardening`; the lead merges it here when green.
- **Docker build not run by design-system.** The Dockerfile's `corepack install` picks up `packageManager: pnpm@12.11.2`, matching CI; a `docker build` (on vdk) has not been run against the new lockfile yet.
- **Bundle:** one 852 kB JS chunk (260 kB gzip), up from the 742 kB baseline measured before the upgrade, mostly Radix and lucide now reached through the CodeBlock shim. Route-level splitting is Phase 2 scope. **Phase 2 result** (production build, 2026-10-14): entry 291 kB (92 kB gzip) plus a shared ds chunk 231 kB (73 kB gzip); first load of `/` is about 182 kB gzip. recharts ships only in the `UsagePage` chunk (362 kB, 104 kB gzip).
- **Static gates, full `src`:** 12 raw hex (LoginPage, UsagePage) and 193 stock palette classes across 11 unmigrated page and layout files. `src/components/ds` is clean. Recommend adding `--primitive-lib radix-ui` to the BRIEF §10 command so pages importing the unified `radix-ui` package directly are caught (the default only matches `@radix-ui/`).
- **Gate script:** does not skip `.pnpm-store/`; keep the pnpm store outside `portal/` or pass `--exclude`.
- **Shared-worktree e2e flake (keys).** `vite dev` full-reloads every open page when any agent edits a shared module (seen for `src/lib/api.ts`), and Playwright's `outputDir` (`portal/e2e/results`) sits inside Vite's watch root, so trace writes also trigger reloads mid-test. Keys ran its spec against a scratch `vite build` served by `vite preview` (`E2E_PORT=5183`, `--output` outside `portal/`). Suggest design-system add `e2e/results` and `playwright-report` to `server.watch.ignored`, or move `outputDir` out of `portal/`.
- **Fixed: gateway 500 on create or roll with an expiry** (postgres.js rejected a `Date` bind). Lead fixed in 85c0fcf; the keys spec's expiring-key case guards it.

- **Fixed (lead, 5424a08): nginx hard loads of `/embed`.** Was: `location /` uses `try_files $uri $uri/ /index.html`, and `/embed/` is a real directory (`v1.js`), so `$uri/` matches it before the `index.html` fallback. Inference from nginx semantics, not run in a container: a reloaded or shared `/embed` link would get a redirect to `/embed/` and a 404. Client-side navigation is unaffected. Fix: `location = /embed { try_files /index.html =404; }`, or drop `$uri/` from `location /`.
- **Source links gated on `VITE_SOURCE_URL`** (lead decision). The repository returned 404 on 2026-10-14; making it public and setting the build argument is the owner's call. Copy still says "open source" (hero) and "MIT licensed" (footer) without a link when the variable is unset; both are true per README.md, but a visitor cannot check them until the source is public.
- **Done: per-route `document.title`** (AUDIT finding 21), see Decisions.
- **Reader search not verified end to end.** It renders only when `VITE_PUBLIC_SEARCH_KEY` is set at build time, and the local stack has no such key, so the dialog, its 401/403 and 429 messages, and result links are type-checked and lint-clean but have not run against `/v1/search`. Needs a publishable key restricted to the portal origin (operator step, BRIEF §11).
- **Reader fallback on version switch is unit-tested only.** WEB, KJV and AVD all have the same 66 books, so the "not in this translation" landing cannot happen on a switch with the seeded stack. `resolveVersionSwitch` is covered in `features/reader/__tests__/chapter-nav.test.ts`; the missing-book redirect is covered in e2e via `/read/WEB/TOB/1`.
- **Anonymous rate limit is shared by every agent's e2e run** (120 per minute per IP on localhost). The reader spec makes about 50 public reads per project; concurrent runs across agents can tip it into 429s. The reader handles that honestly, but the spec would fail.
- **Engine 400 envelope for a short version search** (lead or engine). `GET /v1/versions?search=e` returns `{ success: false, error: { name: "ZodError", message: "<JSON of the issues>" } }`, so `ApiError.message` becomes a JSON blob. The embed picker avoids it by searching from 2 characters; other callers would show it.
- **nginx `/embed` hard load affects the embed builder** (lead; ia-navigation logged the same root cause). A direct visit or reload of `https://praytify.bible/embed` resolves to the `/embed/` directory, not the SPA. Either `location = /embed { try_files /index.html =404; }` or dropping `$uri/` from `location /` fixes it. The e2e reload test passes on Vite only.
- **Resolved: Scalar reference theme and contrast** (lead, 820e245 and 5802003). `/docs?theme=light|dark` themes Scalar in Sacred Dawn and hides its toggle; the portal passes its resolved theme and reloads the frame on change (dc7ca81). Method and syntax colours are AA on every Scalar surface. The pages spec now runs axe inside the cross-origin frame, light and dark, with no exclusion (589f8bc).
- **Resolved: gateway docs copy** now quotes the live translation count from the engine (820e245).
- **Explained: OAuth buttons render on the local stack.** The local gateway reads the main checkout's `.env`, which holds dev OAuth credentials, so `/api/auth-methods` reports all three methods but the OAuth round trip cannot complete in e2e. The pages spec tests the email path for real, checks only that the OAuth buttons match the server's answer, and stubs `/api/auth-methods` for the email-only and none-configured states (lead confirmed).
- **Resolved: static gates, full `src`.** After the page migration the whole tree is clean: 0 identity, 0 raw hex, 0 palette, 0 primitive imports outside `ds/`. Google's four-colour mark is an SVG asset, not page markup.
